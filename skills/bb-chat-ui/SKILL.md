# bb-chat-ui

채팅 표면만 담당한다. 메시지 본문, 메시지 액션, 컴포저다.

기기 판정은 복사한 `lib/use-device.ts`의 `useDeviceChrome()`에서 받은 `device`, `orientation`, `viewport`, `hitTarget`만 쓴다. 복사한 `device.ts`와 `use-device.ts`는 원본 그대로 유지한다. desktop의 글자·버튼 크기는 화면 폭으로 바꾸지 않는다. phone portrait와 landscape는 기존 viewport별 UI를 유지하며, 회전만으로 portrait 배치를 landscape에 적용하지 않는다.

기기별 CSS는 `DeviceChromeBridge`가 HTML 루트에 반영한 `data-bb-chat-ui-root-device`, `data-bb-chat-ui-root-orientation`, `data-bb-chat-ui-root-viewport`, `data-bb-chat-ui-root-hit-target`을 직접 읽는다. 문서 안의 기기 표식을 찾는 전역 `html:has(...)` 조건은 쓰지 않는다. 판정은 기존 공용 헬퍼가 맡고 CSS 전달 경로만 분리한다. 같은 값은 다시 쓰지 않으며, 여러 컴포저는 루트를 공유한다. 스레드 교체 중 같은 commit의 bridge 재연결은 값을 유지하고, 마지막 bridge 해제 후에는 원래 루트 속성을 복구한다. 기존 숨긴 표식은 정보 줄의 기기 변화 감지와 JS 판별용으로 유지한다.

컴포저 초안의 `>` 인용은 호스트 멘션으로 바뀐다. 전문을 저장하는 동안에도 원문 인용은 멘션과 같은 높이와 최대 너비로 제한하고 첫 문단만 보여 준다. 새 멘션에는 첫 화면부터 공통 규격을 적용한다. `diff --git`로 시작하는 코드 인용은 변경 줄 아이콘이고, 파일 이름과 원문에 있는 diff 행 범위를 필에 표시한다. 행 범위가 없으면 파일 이름을 쓴다. 메시지 아래 버튼으로 넣은 인용은 메시지 아이콘이고, 드래그해서 넣은 인용은 인용 아이콘이다. 일반 인용은 첫 줄의 앞부분을 표시한다. 표시용 라벨에서는 굵게·기울임·인라인 코드와 제목·목록·인용 접두 서식을 제거한다. BB가 서식을 먼저 해석해 멘션 노드를 일반 텍스트로 바꾸지 않도록 한다. 보관하는 인용 원문은 유지한다. 전문은 사용자 메시지에 남지 않고, 보낼 때 에이전트에게만 전달된다. 캐럿은 인용 필 안에 머물지 않는다. 백스페이스와 Delete는 인용 필 전체를 지운다.

멘션 필은 작성창, 메시지 편집창, 보낸 메시지, 대기 메시지에서 같은 규격을 쓴다. Agentation, 인용, 파일, 스레드, 스킬을 포함한다. `useDeviceChrome()`의 `device`가 `phone`이고 `viewport`가 `narrow`이면 높이 `32px`, 글자 `14px`와 줄 높이 `18px`, 대표 아이콘 `16px`, 간격 `6px`, 주변 여백 `4px`, 패딩 `6px 14px 6px 12px`, 최대 너비 `240px`다. 그 외에는 높이 `28px`, 글자 `12px`와 줄 높이 `16px`, 대표 아이콘 `14px`, 간격 `4px`, 주변 여백 `3px`, 패딩 `4px 12px 4px 10px`, 최대 너비 `140px`다. 두 환경 모두 부모의 가용 폭 안에 둔다. 짧은 필은 내용만큼 차지하고 긴 필은 한 줄 말줄임이다. 일반 필의 내부 라벨에도 아이콘·패딩·테두리를 뺀 고정 최대 너비를 적용해, 필만 있는 말풍선의 내용 너비 계산에 긴 원문 라벨이 들어가지 않게 한다. 한 줄 컴포저에서도 세로 가운데에 둔다. 코드 변경과 커밋은 일반 최대 너비의 예외로 두고 가용 폭을 쓴다. 커밋은 화면에 해시 앞 7자리만 표시하고 원본 멘션 참조는 유지한다. 작성·편집 중에는 우측 X를 항상 표시하고 그 자리의 패딩을 확보한다. X 모양의 불투명도는 50%다. X는 해당 편집 문서의 멘션 노드를 지우며, 필 본문의 기존 열기 동작과 분리한다. 보낸 메시지의 읽기 상태에는 X가 없다. 새 멘션 추가 때 자동으로 붙은 문단 구분은 공백으로 바꿔 같은 줄에 나란히 놓는다. 기존 초안의 줄바꿈은 유지한다. Add to chat으로 넣은 인용도 필로 바꿀 때 자동 줄바꿈을 정리한다.

컴포저 위 Code Diff는 호스트의 `thread-prompt-banner-git-toggle`과 공개 SDK 환경 상태를 사용한다. 줄 수와 파일 목록은 일반 checkout과 worktree 모두 해당 환경의 `HEAD` 이후 미커밋 변경만 쓴다. 커밋된 코드 라인 수로 대체하지 않는다. 미커밋 변경이 있으면 줄·파일 요약과 보라색 브랜치 아이콘만 표시한다. 미커밋 변경이 없으면 `main`/`master`는 `origin/main`/`origin/master`에 없는 커밋 수를 `↑N`으로 표시한다. 작업 브랜치는 PR 대상 원격 브랜치에 없는 커밋 수를 브랜치명과 함께 표시하고, 미푸시 여부와 숫자는 팝오버에만 둔다. PR 대상은 열린 PR의 base를 우선하고, 없으면 환경의 비교 브랜치 또는 저장소 default branch를 origin의 ref로 사용한다. 개수는 SDK의 `aheadCount`를 사용하며 목록 길이로 세지 않는다. 비교 ref가 실제로 없으면 숫자를 알 수 없음으로 두고 팝오버의 커밋 메타데이터에 `원격 기준 없음 · origin/<브랜치>`를 표시한다. 로컬 브랜치나 전체 커밋 수로 폴백하지 않는다. 조회 중 HEAD가 바뀌거나 일시적으로 조회에 실패하면 불완전한 결과를 표시하지 않고 마지막 정상 결과를 유지한다. 아직 원격 작업 브랜치가 없어도 원격 base가 있으면 PR 후보 수는 계산한다. 원격 비교는 마지막으로 확인한 remote-tracking ref 기준이며 자동 fetch·push는 하지 않는다. 브랜치명은 pill에만 `…` 포함 10자로 제한한다. 팝오버는 main/master를 포함해 보라색 아이콘과 전체 이름을 표시한다. clean main/master의 미푸시 수가 0이거나 원격 기준이 없어 확인할 수 없으면 빈 아이콘 설정과 무관하게 상단 필만 숨기고 전체 정보에서 상세를 유지한다. 미커밋 변경이나 확인된 미푸시 커밋이 있으면 상단 필을 표시한다. detached HEAD에는 브랜치 아이콘이나 후보 커밋 수가 없다. 호스트 펼치기는 숨긴다. 정보 줄의 필과 전체 정보 목록은 먼저 팝오버를 연다. 팝오버 타이틀 옆의 `Diff 패널 열기` 아이콘 버튼이 옆 패널의 Diff 탭을 연다. 컴포저의 `Merge base` 비교 기준 선택기는 숨기며 단독 필 판정에서 제외한다.

스레드 목차는 호스트의 `[data-thread-toc]`다. 탭은 숨긴다. 눈금을 클릭하면 그 눈금의 미리보기 메시지로 스크롤한다. 호스트의 메시지 버튼을 실행해 과거 메시지 로딩도 기존 동작을 따른다. 첫 클릭으로 목록이 열리면 목록이 나타난 뒤 한 번 이동한다. 카드는 마우스가 올라간 눈금의 사용자 메시지 하나만 보여 주고, 미리보기는 6줄까지다. 카드 호버는 배경색 없이 살짝 커지며, 그때도 눈금 길이와 선택 색은 유지된다. 카드 면은 컴포저와 같은 glass다. 블러는 `blur(14px) saturate(1.25)`다. 채움은 해당 채팅의 배경에서 계산한다. 일반 채팅은 `--background`, sidebar 톤은 `--sidebar`다. OKLCH의 밝기만 0.075 올리고 채도와 색조는 유지하며, 밝기는 1에서 제한한다. 불투명도는 라이트 68%, 다크 76%다. 순백 배경에서는 밝기를 더 올리지 않고 기존 얇은 그림자로 구분한다. 채팅 배경 자체는 바꾸지 않는다. 실선은 없다. 가장자리는 흐린 inset `0 1px 3px`다. 라이트는 popover 색 35%, 다크는 foreground 색 8%로 부드럽게 이어진다. 메시지를 연 뒤 포인터가 목차 루트 밖으로 나가면 카드는 닫히고, 지금 레일의 눈금 너비와 선택 색은 비워진다. 루트는 남고 레일 버튼만 바뀌어도 지금 눈금을 비운다. 눈금은 오른쪽 끝에 붙고, 가까울수록 왼쪽으로 길어진다. 색이 진한 눈금은 최신 메시지가 아니라 카드에 나온 메시지다.

사이드바 패널 모션은 `sidebar`다. 스레드 목록의 색과 행 표시는 `bb-thread-theme`다.

전송이 끝나면 `selection` 햅틱이 한 번 난다. 그 응답이 끝나면 `success` 햅틱이 한 번 난다. 끝은 보이는 `Working...` 또는 `Thinking…`가 사라질 때다. 프로비저닝과 백그라운드 작업은 세지 않는다. 응답이 시작될 때는 햅틱을 내지 않는다. 중단 버튼(`Stop run`)을 누르면 `selection` 햅틱이 한 번 난다. 맨 밑으로 버튼을 누르면 `impact-light` 햅틱이 한 번 난다. File Diff에서 파일 코드 블럭을 펼치거나 접는 버튼도 `impact-light`가 한 번 난다. 같은 누름의 클릭과 포인터 업은 한 번만 울린다. 모두 모바일 셸의 `haptic` capability가 있을 때만 낸다.

채팅 면, 스레드 헤더, 안전 영역은 호스트 테마를 그대로 따른다. 이 플러그인은 고정 채팅 캔버스를 선언하지 않는다. 페이드 끝은 일반 채팅에서 `--background`, sidebar 톤의 분할 채팅에서 `--sidebar`다. 첨부 메시지의 접힌 글 페이드도 해당 호스트 표면 위에 `--surface-recessed`를 합성한다. 목록이나 sidebar 플러그인의 색 변수와 설정을 읽지 않는다. 컴포저 뒤의 단색 판은 없다. 페이드는 footer 판의 바닥에 붙고 컴포저 위 64px까지 퍼진다. 높이는 컴포저 높이와 아래 여백, 64px의 합이다. 위는 투명하고, 높이의 45%에서 채팅 면 색 12%, 75%에서 35%, 90%에서 65%로 완만하게 이어진다. 마지막 10%에서 배경색 100%에 닿아 하단 경계를 잇는다. 그 위 구간은 반투명을 유지한다. 일반 채팅과 sidebar 톤은 각각 자신의 배경색을 쓴다. 컴포저는 위로 당겨 올리지 않는다. 펼친 후속 메시지 입력 영역의 최소 높이는 모바일·데스크톱 모두 68px다. 상단 배너 높이를 빼는 호스트의 최소 높이 규칙을 덮어써, 필·버튼의 유무로 입력 영역이 32px 늘거나 줄지 않게 한다. 변경 필, 맨 밑으로 버튼, 컴포저, Agentation staging은 같은 glass 표면색을 쓴다. Chat UI가 켜져 있을 때 Agentation의 고정 채움색을 이 규칙으로 덮는다. 서로의 설정이나 색 변수를 읽지 않는다. 블러는 `blur(14px) saturate(1.25)`다. 채움은 해당 채팅의 배경에서 계산한다. 일반 채팅은 `--background`, sidebar 톤은 `--sidebar`다. OKLCH의 밝기만 0.075 올리고 채도와 색조는 유지하며, 밝기는 1에서 제한한다. 불투명도는 라이트 68%, 다크 76%다. 순백 배경에서는 밝기를 더 올리지 않고 기존 얇은 그림자로 구분한다. 채팅 배경 자체는 바꾸지 않는다. 컴포저, 변경 필, 맨 밑으로 버튼, Agentation staging의 실선은 없다. 가장자리는 흐린 inset `0 1px 3px`다. 컴포저의 상단 반사광은 흰색을 라이트 60%, 다크 14%로 섞는다. 변경 필, 맨 밑으로 버튼, Agentation staging은 라이트 popover 색 35%, 다크 foreground 색 8%를 유지한다. 데스크톱 컴포저 그림자는 `0 12px 32px -14px`이고, 커서가 들어가고 나올 때 320ms, `cubic-bezier(0.2, 0.8, 0.2, 1)`로 바뀐다. `useDeviceChrome()`의 `hitTarget`이 `small`일 때 접고 펼치면 모서리가 480ms, `cubic-bezier(0.22, 1, 0.36, 1)`로 바뀐다. 높이는 360ms다. 호스트는 인라인으로 `height 240ms`를 넣고 320ms에 높이를 비운다. 이 플러그인은 그 문자열만 360ms로 바꾸고, 높이가 비면 같은 곡선의 남은 시간으로 이어 간다. `transition`에는 `!important`를 쓰지 않는다. 접히고 펼쳐질 때 컴포저 내용의 아래 가장자리는 바닥에 남고, 위쪽이 줄어든다. 그때 스크롤이 바닥에서 4px 안이면 애니메이션 동안 스크롤을 바닥에 붙인다. 사용자가 위로 스크롤하면 그 붙임은 멈춘다. `viewport`가 `medium` 또는 `wide`이면 접힌 푸터 줄도 아래에 정렬된다. `device`가 `desktop`인 경우 그 애니메이션 동안 scroll anchoring은 꺼 두고, 판이 스크롤 바닥보다 위로 남으면 `translateY`로 되돌린다. `viewport`가 `narrow`이고 컴포저가 접혀 있으면 푸터는 `100dvh`를 넘지 않는다. 위의 배너가 많아도 컴포저는 아래에 남고, 배너 열만 스크롤된다. `prefers-reduced-motion`이면 모서리는 바로 바뀐다. `hitTarget`이 `large`이면 모서리는 바로 바뀐다. `device`가 `phone`이고 `viewport`가 `narrow`인 화면의 컴포저 그림자는 `0 6px 16px -10px`, 포커스는 `0 8px 20px -12px`다. 필과 맨 밑으로 버튼은 `0 6px 18px -12px`다. 컴포저 모서리는 `1.375rem`이고, 접힌 컴포저는 `999px`다. 접힌 컴포저에 핸드오프 줄(`Exit handoff`)이 있으면 모서리는 `1.375rem`다. 컴포저 안 버튼, 전송 껍데기(`[data-promptbox-send-menu]`), Stop의 바깥 모서리는 `999px`다. 이미지를 담은 미리보기 버튼은 빼 둔다. Stop 안의 네모 아이콘은 그대로다. `/` command와 `@` mention의 후보 박스는 같은 `[class~="@container/mention-menu"]`에만 모서리 `18px`와 카드 가장자리·그림자를 두고, glass 면과 `blur(14px) saturate(1.25)`는 그 루트의 `::before`에만 둔다. 루트는 `position: relative`, `isolation: isolate`, 투명 `background`, `backdrop-filter: none`이다. 배치 wrapper `[data-promptbox-typeahead-menu]`와 plugin interaction drawer는 그대로 둔다. 후보 박스가 열린 footer `[data-promptbox]`는 `background`를 투명하게 하고 `backdrop-filter`를 끄며 `isolation: isolate`로 둔 뒤, 그 `::before`에 기존 light/dark glass 면과 `blur(14px) saturate(1.25)`를 옮겨 원래 `box-shadow`를 유지하고, `.sticky.bg-background` 헤더는 투명 배경과 같은 블러만 쓴다. 후보 목록의 첫 `.overflow-y-auto`만 `overscroll-behavior: contain`으로 두어 목록 끝과 짧은 목록의 휠을 그 목록 안에 둔다.

대기 메시지 큐도 전체 정보에서 여는 한 정보 계열이다. 정보 줄이 큐를 관리하면 기존 숫자 버튼과 native header를 숨기고 새 큐 버튼만 진입점으로 남긴다. 기존 standalone 큐의 위치·높이 CSS와 자동 접기·클릭 처리는 이 큐에 적용하지 않는다. 팝오버는 실제 native 목록과 편집·전송·삭제 동작을 그대로 쓰고, 내부 목록은 제한된 높이에서 스크롤된다. 큐 DOM 노드는 다른 부모로 옮기지 않는다. 정보 줄이 관리하지 않는 standalone 큐에만 다음 레이아웃과 접기 규칙을 적용한다. 접힌 큐는 메시지 개수만 보이는 원형 버튼이다. 호스트의 실제 toggle 버튼을 원형 숫자 영역 전체에 남겨 클릭과 키보드 입력을 받는다. 누르면 메시지 행이 버튼 바로 위에 absolute로 펼쳐지고, 버튼은 아래쪽 화살표로 바뀐다. 행이 접힌 Agentation과 세로로 겹치는 경우에만 Agentation 오른쪽 가장자리에서 8px 뒤부터 폭을 쓴다. 나머지는 전체 폭을 쓴다. 긴 목록은 열린 영역 안에서 스크롤된다. 펼쳐도 큐 슬롯 높이는 32px로 고정한다. 모든 정보 계열의 전체 정보 목록과 각 상세 팝오버는 실제 스크롤할 내용이 남은 방향에만 테마 기반 블러 그라데이션을 표시한다. 처음에는 아래, 중간에는 양쪽, 끝에서는 위에 표시하며, 내용이 짧으면 표시하지 않는다. 대기 메시지처럼 내부 목록이 스크롤되는 경우 그 영역을 따라간다. 힌트는 클릭과 키보드 입력을 막지 않고 해제 시 관찰자와 리스너를 정리한다. 상세는 한 번에 하나만 펼친다. 큐 행 편집 중에는 편집 내용을 잃지 않도록 상세 전환과 닫기를 막는다. 플러그인을 끌 때도 열린 큐 편집기를 강제로 접지 않는다. 정보 줄이 관리하는 큐 상세의 행은 말풍선 없이 본문을 왼쪽, native 액션을 오른쪽에 놓는 간결한 목록이다. 본문은 가용 폭을 쓰고 `12px`, 줄 높이 `1.5`로 표시한다. 행의 세로 패딩은 `4px`이고, 행 사이에 얇은 구분선을 두며 본문과 액션 묶음의 배경·그림자는 없앤다. 드래그 핸들·…·수정·전송·삭제 액션은 메시지 행 전체의 세로 중앙에 정렬한다. 기본 액션 터치 영역은 32px이고 본문 세로 패딩은 8px다. `hitTarget`이 `small`이면 액션은 24px, 본문 세로 패딩은 4px로 압축한다. 멘션 필과 편집·전송·삭제 동작은 유지한다. 아래 말풍선 규칙은 standalone 큐에만 적용한다. standalone 큐 행은 사용자 메시지와 같은 오른쪽 말풍선이다. 면은 `surface-recessed`, 테두리는 `border-seam`, 모서리는 `calc(var(--radius) + 4px)`, 글자는 `text-sm` `leading-relaxed`다. `var(--radius-xl)`은 쓰지 않는다. `--radius-xl`은 Tailwind `@theme inline` 안이라 런타임 변수가 아니다. 알약과 말풍선의 불투명도는 1이다. 큐의 일반 텍스트에 적용하는 줄바꿈·글자 크기 규칙에서 멘션 필과 그 자식을 제외해, 필 내부는 공통 한 줄 말줄임 규격을 유지한다. 그 왼쪽에 호스트의 삭제·보내기·편집 버튼이 말풍선과 같은 높이에 있다. 말풍선과 버튼 묶음에는 같은 옅은 그림자를 넣는다. 그림자는 `0 4px 12px -4px`이고 라이트는 잉크색 20%, 다크는 검정 50%다. 그림자가 잘리지 않도록 스크롤 목록 안쪽에 4px 여백을 둔다. 접고 펼치면 목록 높이가 260ms, `cubic-bezier(0.16, 1, 0.3, 1)`로 바뀐다. `prefers-reduced-motion`이면 바로 바뀐다. 처음 보이는 drawer는 호스트 동작으로 한 번 접는다. 이미 접힌 상태로 처음 보인 큐는 사용자의 첫 펼침을 다시 접지 않는다. 메시지가 많아 호스트 caret가 workspace 열기 역할을 할 때는 숨긴 surface handle의 Escape 동작으로 접는다. 인라인 편집이 열려 있으면 초기 자동 접기를 하지 않는다.

보낸 사용자 메시지의 사진과 파일은 말풍선 바로 위에 있다. 사진이 위이고, 파일이 그 다음이고, 그 아래가 글이다. 간격은 `8px`다. 파일 필의 패딩은 `6px 14px 6px 12px`다. `useDeviceChrome()`의 `device`가 `phone`이고 `viewport`가 `narrow`이면 최소 높이 `64px`, 모서리 `20px`, 아이콘 `28px`다. 그 외에는 최소 높이 `40px`, 모서리 `12px`, 아이콘 `18px`다. 말풍선 면은 글자 칸 `.break-words`에 있다. 면은 `surface-recessed`, 테두리는 `border-seam`, 모서리는 `calc(var(--radius) + 4px)`, 패딩은 `0.625rem 1rem`다. 글이 없는 `Sent attachments` 문장은 숨긴다. 긴 글의 `Show more`는 말풍선 아래 패딩 안에 둔다. 첨부가 있는 접힌 메시지의 높이 한도는 `calc(15lh - 8px)`다. 페이드는 글자 칸의 보이는 아래쪽에 겹친다. 페이드의 기준은 실제 잘리는 영역의 하단이다. `Show more` 자리까지 단색 구간을 이어서 마지막 글과 버튼이 겹치지 않게 하고 테두리는 유지한다.

화면을 바꾸는 등록은 `app.tsx`에 둔다. 인용 전문은 `server.ts`가 보관하고, 전송 때 멘션으로 읽는다.


## 컴포저 위 정보

Child Thread 아바타의 안쪽은 제목 이니셜 대신 해당 스레드의 provider 아이콘으로 표시한다. 공개 SDK `experimental_useProviders`의 provider record와 `experimental_ProviderIcon`을 사용해 등록된 custom renderer·logo·glyph·테마 tint를 따른다. 상단의 30px 스택과 상세 목록의 27px 원 안에 16px 아이콘을 중앙 정렬하며 상태 점·완료 체크·최대 세 원과 `+N`·기존 모션은 유지한다. provider가 등록되지 않았으면 SDK의 `UserRound` fallback을 사용하고, 아이콘을 제공하지 않는 이전 source에는 제목 이니셜을 유지한다. provider 정보가 늦게 도착하거나 갱신되어도 같은 child ID의 아이콘을 갱신하고 새 스레드의 등장 모션을 반복하지 않는다.

`비활성 정보 표시` (`showInactiveInfo`)는 기본 꺼짐이다. 내용 없는 계열은 스택과 전체 목록에 표시하지 않고 비활성 정보용 +N 너비도 예약하지 않는다. 활성 정보가 너비 부족으로 접히거나 목록 전용이면 스택에서 접근한다. 옵션을 켜면 내용 없는 계열도 `현재 없음`으로 포함한다. 아이콘은 최대 세 개이며 +N은 그 뒤에 남은 활성 계열 수, 옵션을 켰으면 남은 전체 계열 수다. `끄기`는 항상 제외한다. 이전 `showEmptyIcons` 설정은 사용하지 않는다. 각 아이콘은 해당 계열 상세를 열고 +N은 전체 목록을 연다.

`composer-info` content script가 호스트 카드를 원래 DOM 부모에 둔 채 압축한다. 기본값은 15종 모두 `상단 표시`이며, 내용이 있는 계열만 상단에 표시한다. 내용이 없는 계열은 비활성 정보 표시 옵션을 켠 경우에만 전체 정보 목록에 남긴다. `Settings → Chat UI`에서 각 계열을 `상단 표시`, `목록에만 표시`, `끄기` 중 하나로 설정한다. `끄기`는 상단과 전체 정보 목록 모두에서 제외하며, 전부 끄면 정보 줄도 숨긴다. 실제 컨테이너의 너비를 측정해 한 줄에 안 들어가는 항목은 전체 정보 안에 접는다. Code Diff와 Child Thread를 먼저 배치하며, 넘친 정보와 목록에만 표시하는 정보는 전체 정보에서 열 수 있다. 설정 안내에도 자동 접힘을 설명한다. 맨 아래로 버튼 자리는 아래 배치 규칙에 따라 예약한다. desktop의 버튼·글자 크기는 viewport 폭으로 바꾸지 않는다.

Archived thread와 환경 제거 상태에서는 상단의 다른 pill과 전체 정보 원 버튼을 숨기고 전체 너비의 상태 pill 하나만 표시한다. native 상태 카드가 있는 동안 공개 SDK의 archive·환경·host lifecycle을 우선하고, 조회 전에는 native `Thread history`의 상태 접근성 라벨로 판별한다. 복구 후 native 상태 카드가 사라지면 SDK의 이전 조회 결과가 남아 있어도 즉시 일반 정보 줄로 돌아간다. 내용 없는 아이콘 표시 설정이 켜져 있으면 일반 크기의 빈 상태 아이콘만 유지하며, 전체 너비의 빈 상태 필로 남기지 않는다. Archived는 `Archived thread`, 환경 제거는 `Environment unavailable`, host 제거·제거 중·정리 실패는 각각의 상태 라벨을 표시한다. 상태 pill은 표시 설정과 너비 부족으로 숨기지 않는 필수 안내다. 클릭하면 닫기와 복구 버튼만 있는 팝오버를 연다. 상위 스레드·다른 정보·전체 정보 목록 진입은 제공하지 않는다. `Unarchive`는 공개 SDK의 `threads.unarchive`를 직접 실행하므로 상위 스레드가 있어 native 버튼이 생략되어도 작동한다. 환경 복구는 SDK의 `canRestoreEnvironment`가 참일 때만 `threads.restoreEnvironment`를 실행하고, 거짓이면 비활성 `복구 불가` 버튼을 표시한다. host가 제거되었거나 활성 상태가 아니면 현재 BB는 환경 복구를 허용하지 않는다. archive와 환경 제거가 겹치면 Unarchive부터 제공한다. Unarchive·환경 복구도 공통 글자 액션을 사용한다. 글자는 `11px`/`16px`, 높이는 small hit target에서 `28px`, large에서 `32px`이며 정보 pill의 글꼴 규칙에 덮이지 않게 한다. 복구 중에는 중복 실행을 막고 pending 상태를 표시하며, 실패하면 실제 오류를 표시하고 재시도할 수 있다. 다른 정보의 데이터와 개별 표시 설정은 유지하며 복구 후 일반 정보 줄로 돌아간다. 입력 요청이 있으면 상태 안내보다 요청을 우선한다.

정보 줄의 필·원 버튼과 팝오버의 바깥면은 `glass-surface.ts`의 컴포저 표면 계산을 공유한다. 팝오버 안 버튼은 `lib/info-card.ts`의 공통 액션을 사용하며 추가 frost·그림자를 겹치지 않는다. 채팅은 `--background`, sidebar는 `--sidebar`를 기준으로 색조를 유지하고 밝기만 `0.075` 올린다. 투명도는 라이트 `0.68`, 다크 `0.76`이며, `blur(14px) saturate(1.25)`와 주변 버튼의 부드러운 inset 하이라이트를 적용한다. Child Thread는 스택 바탕 없이 각 아바타만 테마 표면에 색상을 섞고, 테두리도 해당 채팅 배경을 따른다. 상세는 한 번에 하나만 펼친다. 같은 필을 다시 누르거나 Escape를 누르면 닫히고, 다른 정보를 누르면 교체된다. 큐 편집 중에는 교체·닫기를 막는다. 설정에서 대기 메시지를 꺼도 편집이 끝날 때까지 열린 상세를 유지한다. 호스트 disclosure와 원래 버튼을 실행해 기존 열기·삭제·승인 동작을 보존한다. 여러 Workflow나 플러그인 안내는 전체 정보에서 각각 선택할 수 있다. Code Diff는 합계와 브랜치뿐 아니라 실제 SDK의 수정 파일·파일별 추가/삭제 줄 수·비교 기준·브랜치 커밋 목록을 팝오버에 표시한다. 파일 목록은 항상 `HEAD` 이후 미커밋 변경 기준이며, 변경 중에는 열린 상세도 갱신한다. PR 후보와 미푸시 커밋 수는 각각의 origin 비교 대상을 명시한다. 줄 수가 없는 파일은 `통계 없음`으로 표시한다. 기준 브랜치 대비 커밋을 미푸시 커밋으로 표시하지 않는다. `Diff 패널 열기`를 눌렀을 때 팝오버를 닫고 옆 Diff 패널을 연다. 상위 스레드·PR·Diff가 한 호스트 카드에 속해도 각 팝오버는 원래 카드를 연다. Parent 탐색은 `lib/info-card.ts`의 `single-row` 규격에 연결한다. 별도의 Parent 제목 행 없이 부모 provider 아이콘·부모 제목·닫기를 한 줄에 두며, `cardSlot.layout="single-row"`와 `cardSlot.row`를 사용한다. 부모 metadata가 오기 전이나 조회가 실패하면 이 카드의 native 링크 제목만 임시 행으로 두고, 다른 스레드의 provider나 제목은 쓰지 않는다. 그 부모가 없어지면 행을 지우고 이전 부모로 이동하지 않으며, native 카드를 다시 보여 빈 팝오버로 두지 않는다. 관계 설명과 중복 native 사람 아이콘 행은 숨긴다. 행을 누르면 공개 SDK `navigate.toThread` 또는 원래 native 링크로 부모 스레드를 연다. 닫기는 팝오버만 닫는다. Parent가 열린 동안 Diff·PR은 숨기고, 노드의 DOM 부모와 disclosure는 유지한다. 닫기·해제 시 추가한 행을 제거하고 standalone 카드를 복원한다. PR 팝오버도 `single-row`의 32px 행에 PR 제목·외부 열기·Merge·닫기만 표시한다. 별도 계열 제목·계열 아이콘·상태 본문은 추가하지 않는다. SDK 대체 카드도 같은 행을 쓴다. Merge는 테두리·배경 없이 글자와 캐럿만 보이며 둘 다 기존 머지 방식 메뉴를 연다. 방법 선택 시에만 실행한다. Parent·Diff 토글과 Parent 본문은 숨긴다. Diff는 자체 팝오버를 쓴다.

현재 스레드 또는 Child Thread의 입력 요청이 있으면 정보 줄과 나머지 배너, 입력창을 숨기고 요청을 컴포저 바로 위에 둔다. 초안은 수정하거나 지우지 않는다. 요청이 해소되면 정보 줄과 입력창이 복원된다. Archived와 환경 제거 상태에서는 위의 단일 상태·복구 팝오버 규칙을 따른다. 호스트가 생략하는 Plan·Goal·할 일·Child Thread·대기 메시지·PR은 공개 SDK의 읽기 전용 요약으로 보완한다. Diff 요약은 실제 환경 상태를 쓰며, 미푸시 수는 origin의 현재 브랜치 ref와 비교하여 읽는다. 해소되지 않는 ref의 SDK 0은 실제 0으로 표시하지 않는다.

Child Thread는 배경 없는 30px 색상 아바타 스택이다. 마지막 세 스레드를 왼쪽에서 오른쪽으로 겹쳐 보여 주며, 오른쪽 원이 앞에 놓인다. 표시한 수보다 많으면 스택 맨 오른쪽의 별도 30px 원에 전체 개수에서 표시한 수를 뺀 `+N`을 표시한다. 정보 줄의 남은 너비가 모자라면 접기 전에 마지막 두 개, 다시 마지막 한 개로 줄인다. 너비는 실제 측정한 스택 너비에 원 하나당 18px(30px 원, 12px 겹침)를 더하거나 빼서 계산하며, 맨 아래로 버튼 출현·소멸, 창 크기 변경, 다른 pill과 Child Thread 수 변화 때 다시 맞춘다. 같은 너비면 원을 더 많이 보여 준다. 한 개도 들어가지 않으면 기존 규칙대로 전체 정보에 접힌다. 전체 개수는 접근성 라벨과 툴팁에 남긴다. 실행·입력/호스트 대기·종료·오류를 점과 체크로 구분하며, 점과 완료 체크는 각 아바타 왼쪽 아래에 둔다. 기본 점은 `left:0` `bottom:0`, 완료 체크는 `left:-2px` `bottom:-2px`이고 `right`는 `auto`다. 제목에서 두 글자 이니셜을 만든다. 상세는 공개 SDK 데이터로 아바타·제목·provider·상태 행을 그리고, 각 행 전체를 하나의 버튼으로 두어 실제 스레드를 연다. 행은 손 모양 커서, 10px 둥근 모서리와 8px 여백을 쓰며, hover와 키보드 포커스에는 테마 foreground 6%의 옅은 배경을 표시한다. 새 Child Thread 아바타는 bubble처럼 튀어나오고, 실행 중 상태 점은 천천히 호흡한다. 완료 시 짧게 반응한 뒤 정지한다. 정보 내용이 바뀐 pill은 420ms `eventHop`으로 반응하고, 전체 정보 버튼은 자기 배지나 아이콘이 바뀔 때만 같은 hop을 한다. `prefers-reduced-motion`이면 모션을 생략한다. 해제·reload 시 플러그인이 만든 DOM·스타일·속성·관찰자·리스너·예약 작업을 정리한다.

Agentation은 BB 브라우저 `Annotate elements` 버튼과 같은 SDK `MessageSquarePlus` (`BubbleChatAddIcon`)와 실제 staged 개수만 필에 표시한다. 빈 상태·전체 정보 목록·상세 제목과 행도 같은 glyph를 사용한다. SDK 아이콘이 늦게 준비되어도 개수 변경 없이 표시를 갱신한다. 원래 카드의 `ChatFeedback` 제목 아이콘은 관리되는 팝오버 안에서만 숨기며 원래 DOM을 유지한다. 상세는 피드백 본문과 위치·대상 정보를 두 줄로 나누고, 각 행 앞에 같은 아이콘을 둔다. 행 구분선은 없애고 공통 최소 높이 32px·여백 8px·둥근 모서리 10px·행 간격 2px를 사용하며 두 줄 내용에 맞춰 높아진다. hover와 내부 버튼의 키보드 포커스에는 Child Thread와 같은 테마 foreground 6% 배경을 표시한다. 열린 팝오버에서는 본문의 native grid와 바로 아래 래퍼의 overflow를 visible로 바꿔 좌우로 넓힌 행 배경과 버튼 그림자가 잘리지 않게 한다. 스크롤 경계는 카드 자체에 유지하고, 닫기·해제하면 native overflow로 돌아간다. 전체 전송·삭제 버튼은 제목 행의 × 왼쪽에 아이콘으로 둔다. 원래 Agentation DOM과 개별 멘션·전송·삭제, 확인 dialog, 오류 재시도 동작을 유지하며, 상단 X는 원래 접기 동작으로 상세를 닫는다.

정보 계열의 아이콘 매핑은 서로 겹치지 않게 한다. Plan은 `FileText`, 할 일은 `ListTodo`, Parent는 `MessageSquare`, 스레드 상태는 Thread Theme의 Status와 같은 심박선 glyph를 로컬 `bb-chat-ui-status`로 등록해 사용한다. 실행 환경은 `Laptop`, 백그라운드 작업은 `Terminal`, 기타 정보는 `Info`, Model fallback은 `AlertTriangle`로 구분한다. 다른 플러그인의 등록이나 설정에 의존하지 않는다. Plan·스레드 상태·실행 환경·기타 정보의 pill에는 native 카드의 중복 아이콘보다 계열 아이콘을 우선하며, 빈 상태와 전체 정보 목록에도 같은 아이콘을 쓴다. 아이콘이 늦게 준비되어도 정보 값의 변경 없이 표시를 갱신한다.

정보 줄의 모든 필·아바타 스택·전체 정보 원 버튼과 펼친 목록의 버튼은 사용자 클릭당 `impact-light` 햅틱을 한 번 낸다. 터치·마우스·키보드 활성화를 같은 click 경로에서 처리한다. 호스트 disclosure에 전달하는 합성 클릭과 pointerup은 추가 진동을 만들지 않는다. 빠르게 다른 정보를 선택해도 각 클릭을 처리하며, disabled 버튼과 `haptic` capability가 없는 셸에서는 울리지 않는다.

정보 pill과 전체 정보 버튼을 누르면 누르는 동안 120ms에 `scale(.9)`로 줄고, 떼면 380ms 동안 `scale(.9)` → `1.1` → `.97` → `1`로 돌아온다. 포인터, 마우스, Enter·Space 키보드가 같고, 키 반복은 한 번만 누른다. 오른쪽 캡슐에서는 캡슐 전체가 움직인다. 너비·높이·여백·간격과 독립 `translate`는 바꾸지 않고 `transform`만 바꾼다. 빠르게 다시 누르면 이전 press를 취소하고 새로 시작한다. `pointercancel`, window blur, bar 밖에서 손을 떼는 것, disabled와 `prefers-reduced-motion`에서는 생략하거나 누른 상태를 풀고, pill이 사라지거나 해제·스레드 이동·입력 요청이 오면 진행 중인 press를 취소한다. 끝난 pop·hop·출발·착지 애니메이션은 추적에서 빼고, 누르고 있는 `fill: forwards`만 뗄 때까지 유지한다. 햅틱과 팝오버 열기·닫기는 클릭 경로 그대로다.

기존 boolean 설정을 쓴 설치를 업그레이드할 때는 빌드·reload 전에 `bb plugin config bb-chat-ui --json`의 값을 보관하고, reload 후 같은 키에 `true → 상단 표시`, `false → 목록에만 표시`로 저장해 선택을 유지한다.

Code Diff pill의 커밋 수는 `commits` 문구 대신 가운데 원과 가로선이 있는 커밋 아이콘과 숫자로 압축한다. 접근성 라벨과 툴팁에는 커밋 개수 의미를 유지한다. 팝오버에 HEAD 이후 변경 파일이 있으면 항상 커밋 제목과 목록보다 위에 둔다. 열린 팝오버를 갱신해도 같은 순서를 유지한다. 커밋 행 왼쪽의 원을 세로선으로 연결하고 첫·마지막 원 밖으로는 선을 늘리지 않는다. 파일 행 왼쪽에는 BB 스레드 정보의 실제 glyph와 같은 아이콘을 둔다. 수정은 `DiffModified`, 추가와 미추적(`??`)은 `DiffAdded`, 삭제는 `DiffRemoved`, 이름 변경은 `DiffRenamed`, 복사는 `Copy`, 충돌은 `DiffConflict`, 상태 불명(`?`)은 `CircleQuestion`이다. 추가·미추적은 `text-diff-added`, 삭제는 `text-diff-removed`, 충돌은 `text-destructive`, 나머지는 `text-subtle-foreground`를 사용한다. 파일 경로와 라인 통계, 기존 아이콘 크기와 행 배치는 유지한다. 팝오버의 일반 안내 문구는 표시하지 않으며, PR 후보의 미푸시 보조 줄은 개수를 확인할 수 있을 때만 표시한다.

Code Diff 팝오버는 상단 요약 영역에 현재 브랜치·HEAD 대비 작업트리 변경·origin 대비 커밋 수와 비교 ref·확인 가능한 미푸시 수를 모으고 아래 목록과 테마 기반의 얇은 `hr`로 구분한다. 유효한 `files`·`commits` 배열은 길이가 0이어도 `hr`, `변경 파일 · N`, `hr`, `커밋` 순서를 유지한다. 길이가 0인 쪽은 제목 아래 한 줄을 ASCII `-`로 두고, 항목이 오면 그 줄을 기존 목록으로 바꾼다. 비교 ref·커밋 수·미푸시 보조 정보는 상단 요약에만 표시한다. 열린 팝오버가 갱신되어도 제목과 구분선을 중복하지 않는다.

Code Diff의 첫 로딩 상태는 최소 500ms 유지한다. 결과가 빨리 와도 남은 시간만 기다린 뒤 정보 표시 또는 빈 결과의 퇴장 모션으로 이어진다. 500ms를 넘긴 조회와 이후 재조회에는 추가 지연을 두지 않는다. 대기 중 스레드·환경이 바뀌거나 해제되면 타이머를 정리하고 지난 결과를 표시하지 않는다.

Diff 재조회는 마지막 정상 표시를 유지한 채 진행한다. 메시지 스트림·제목 등 환경과 무관한 스레드 변경으로 데이터를 비우거나 재조회하지 않는다. 환경 변경과 5초 polling·focus에서 완성된 결과로 교체하며, 조회 중 변경 이벤트가 오면 이전 요청 결과를 버린다. 다른 스레드로 이동하면 이전 스레드 데이터를 표시하지 않고, 환경 해제는 확인된 뒤 비운다.

컴포저 정보 팝오버의 스크롤은 채팅으로 전달하지 않는다. 내부 목록·편집기의 기본 wheel·한 손가락 스크롤은 유지하고, 팝오버가 짧거나 위·아래 끝인 경우 바깥 스크롤로 이어지지 않게 한다. 팝오버 밖의 채팅 스크롤과 pinch zoom은 유지하며 해제 시 관련 리스너를 정리한다.

스레드 첫 진입에서 Diff SDK source가 아직 비어 있으면 작은 브랜치 아이콘과 세 점의 순차 로딩 애니메이션으로 상단 필을 먼저 표시한다. 임시 호스트 줄 수나 브랜치명은 표시하지 않는다. 최초 정상 결과가 오면 같은 필의 너비를 320ms로 바꾸고, 정보는 240ms로 나타낸다. 너비 계산은 애니메이션 중에도 최종 너비를 기준으로 한다. 빈 아이콘 설정과 무관하게 로딩을 표시하되 `목록에만 표시`·`끄기`·입력 요청·자동 접힘 설정을 따른다. 환경이 없거나 SDK가 `non_git_environment`·`not_git_repo`를 확인하면 로딩을 끝내고 상단 필을 숨긴다. Git이 없다는 확인은 PR 조회 완료를 기다리지 않는다. 첫 조회 실패도 로딩을 끝내고 다음 polling·focus에서 재시도한다. 재조회 실패는 마지막 정상 정보를 유지한다. clean main/master면 상단 필을 숨긴다. 기존 정상 정보가 있는 재조회는 로딩으로 되돌리지 않는다. 전체 정보 목록은 유지하고 `prefers-reduced-motion`이면 점·너비·정보 모션을 생략한다.

Diff 팝오버의 커밋 목록은 SDK `authoredAt` 기준 최신순으로 표시한다. 동일 시각은 원래 상대 순서를 유지하며, 팝오버를 연 상태에서 목록이 갱신되어도 같은 정렬을 적용한다.

Diff 팝오버의 파일·커밋 목록은 각각 5개까지 먼저 보여 준다. 5개를 넘는 항목은 `N개 더 보기` 행으로 접고, 누르면 해당 목록만 펼친다. 펼친 뒤에는 같은 행의 `접기`로 돌아온다. `더 보기`·`접기`는 별도 배경·그림자·블러 없이 화살표와 텍스트만 있는 행으로 표시하고 키보드 focus outline은 유지한다. 5개 이하는 접기 행을 만들지 않는다. 열린 팝오버의 데이터 갱신은 각 목록의 펼침 상태를 유지하고, 팝오버를 다시 열면 기본 상태로 돌아온다. 접힌 커밋 그래프는 다섯 번째 원에서 끝나며 숨긴 행은 스크롤 공간을 차지하지 않는다.

정보 줄에서 여는 대기 메시지 큐는 Code Diff와 같은 `--bb-chat-ui-info-max-height`를 최대 높이로 사용한다. 팝오버 패딩은 공통 세로 `16px`·좌우 `24px`, 내부 메시지 스크롤 목록의 패딩은 세로 `4px`·좌우 `0`으로 두어 메시지가 가장자리에 붙지 않게 한다. 큐 타이틀 아래 간격은 `12px`로 두어 본문과 조금 더 구분한다. 짧은 목록은 내용만큼 줄어들고, 긴 목록은 호스트의 내부 메시지 목록에서만 스크롤한다. 팝오버와 애니메이션 frame에는 별도 스크롤을 만들지 않는다. 기존 행의 편집·전송·삭제와 편집 중 초안 보호, 남은 스크롤 방향의 블러 힌트를 유지한다.

대기 메시지 큐의 계열 아이콘은 Hugeicons `MessageDelay02Icon`의 실제 glyph를 로컬 `bb-chat-ui-queue`로 등록해 사용한다. 말풍선 우측 상단에 작은 시계가 있는 모양이며 pill·전체 정보 목록·빈 상태에 같은 16px 아이콘을 표시한다. 호스트 disclosure의 숨겨진 화살표를 복제해 큐 아이콘을 없애지 않는다.

전체 정보 버튼은 마지막 visible pill 뒤에 붙는 정보 아이콘 스택이다. 32px 원을 최대 세 개 겹치고 나머지는 별도 +N 원으로 표시한다. 접힌 활성 정보는 먼저 배치하며 왼쪽 아래 점을 표시하고, +N 뒤에도 활성 정보가 있으면 +N에 점을 둔다. 표시 공간은 스택의 콘텐츠 너비로 계산한다. Latest는 스택과 분리한 32px 독립 원형 버튼이며 모든 기기에서 같은 줄 오른쪽 끝에 고정한다. 호스트 클릭·햅틱을 그대로 전달하고, 열린 팝오버에서도 표시한다. 버튼이 보일 때 너비 32px와 간격 8px를 예약한다. 기존 떠오름·퇴장 전환은 유지한다. glyph는 평소 정지한다. 정보 내용이 바뀐 pill은 420ms `eventHop`으로 7px 올라갔다가 착지하고, 팝오버 열기·닫기는 hop하지 않는다. 큐에 메시지가 추가된 signature는 hop하지 않고 `stickyDrop`만 재생한다. Diff 숫자 룰렛은 hop과 함께 유지한다. 첫 등장 droplet이 끝나기 전과 `prefers-reduced-motion`에서는 hop을 생략한다. 해제 시 진행 중인 hop도 정리한다. 외부 이미지 에셋은 포함하지 않는다.

상단 정보 pill과 전체 정보 원 버튼은 채팅에 진입해 처음 실제로 표시될 때 Child Thread 아바타와 같은 460ms 물방울 모션을 왼쪽부터 순차 재생한다. 같은 컴포저 DOM을 재사용해 다른 스레드로 이동해도 진입 순서를 다시 재생한다. 입력 요청이나 너비 부족으로 숨겨진 pill은 처음 보일 때까지 기다린다. 같은 스레드의 데이터 갱신·설정 재활성화·크기 변경으로 이미 표시했던 계열의 모션을 반복하지 않는다. Child Thread 스택은 개별 아바타 모션으로 같은 순서에 참여한다. 너비 계산은 모션의 scale과 무관한 레이아웃 너비를 사용하며, `prefers-reduced-motion`이면 모션을 생략하고 해제 시 진행 중인 모션을 취소한다.

다른 계열의 데이터가 갱신되어도 내용이 같은 pill의 내부 DOM은 유지한다. Diff 도착이 진행 중인 Child Thread 아바타 모션을 끊지 않으며, pill이나 전체 정보 버튼의 진입 droplet이 재생되는 동안에는 그 요소의 `eventHop`을 겹치지 않는다.

컴포저의 입력 요청 카드(`tool-use-ask`, `plugin-request-banner`, `user-question-banner`)는 모서리 `18px`와 하단 중심의 `260ms` 등장 전환을 사용한다. 8px 아래·98% 크기·투명 상태에서 원래 위치·크기·불투명도로 나타난다. `plugin-request-banner` 안 실제 면인 `plugin-interaction-shell`에도 같은 모서리를 적용해 native 하단 margin 위의 카드 모서리가 각져 보이지 않게 한다. 내부 카드에 등장 전환을 중복 재생하지 않는다. 선택지·다음·응답·펼치기·접기 버튼의 실제 사용자 클릭에는 `selection` 햅틱을 한 번 낸다. 터치와 클릭, native 버튼에 전달한 synthetic 클릭은 중복으로 울리지 않는다. disabled 버튼·직접 입력·과거 질문에는 울리지 않고 모바일 셸의 `haptic` capability가 있을 때만 낸다. native 선택지·직접 입력·응답 동작과 과거 메시지의 질문 표시는 유지한다. `prefers-reduced-motion`이면 전환 없이 표시한다.

팝오버의 사이드 패널·플러그인 페이지 열기는 타이틀 바로 옆의 작은 외부 열기 아이콘으로 표시한다. 제목 텍스트와의 간격은 8px이며 카드 오른쪽 끝으로 밀지 않는다. PR의 GitHub 링크와 Workflow 외부 열기에도 같은 규칙을 적용한다. 긴 제목은 액션·닫기 자리를 남기고 말줄임한다. 제목 영역(아이콘 포함)과 본문은 같은 왼쪽 시작점을 사용하며 목록 hover 확장 여백을 본문 전체에 적용하지 않는다. 기존 목적지와 동작을 유지하고 툴팁·접근성 라벨로 목적지를 구분한다. 해당 액션이 있을 때만 아이콘을 제공한다. 호스트 버튼·링크는 원래 부모에 남긴 채 숨기고 아이콘 클릭을 원래 액션에 전달한다. disabled 상태와 DOM 갱신을 반영하며 해제 시 원래 표시를 복원한다. 전송·삭제 등 다른 액션은 압축하지 않는다.

정보 줄이 관리하는 팝오버에서는 카드 전체를 접는 native 하단 핸들을 숨긴다. Plan·Goal·할 일·Workflow·백그라운드 작업·실행 환경·스레드 상태·상위 스레드·대기 큐에 적용하며, 여러 Workflow를 묶는 하단 핸들도 별도 정보로 노출하지 않는다. 타이틀 행 오른쪽의 작은 `×`로 팝오버만 닫고 pill 재클릭과 Escape도 유지한다. Plan 종료·Goal 해제 등 실제 기능 액션은 원래 부모와 동작을 유지하고, 파일·커밋·내부 목록의 펼치기/접기는 숨기지 않는다. Child Thread·Agentation·자체 팝오버에 있는 닫기 버튼을 중복 추가하지 않는다. native DOM 갱신에도 닫기 버튼을 복원하며, 플러그인 해제 시 추가한 버튼·표시 속성을 제거해 standalone 카드를 원상 복구한다.

전체 정보 목록과 Parent·PR 단일 행 카드를 제외한 정보 팝오버는 타이틀 왼쪽에 해당 계열의 SDK 아이콘을 14px로 표시한다. Parent에는 별도 타이틀이나 계열 아이콘을 추가하지 않고 한 행에 provider 아이콘과 부모 제목을 표시한다. 빈 상태·Code Diff·Archived 및 환경 복구 상세에도 적용한다. 기존 제목 glyph는 원래 DOM에 두고 중복 표시만 숨기며 실제 액션 아이콘은 유지한다. SDK 아이콘이 늦게 준비되거나 native 제목이 다시 렌더되어도 갱신하고, 닫기·플러그인 해제 시 원래 제목 아이콘을 복원한다.

Goal 팝오버는 native `Goal controls` 헤더 대신 아이콘이 있는 공통 `Goal` 제목을 사용한다. native 헤더의 ring·배경·테두리와 본문의 `bg-popover`·상단 테두리를 제거해 카드 glass만 남긴다. 상단 `×`는 팝오버만 닫으며, native Goal 해제 버튼은 DOM 부모와 동작을 유지한 채 제목 행의 `×` 왼쪽에 `Goal 해제` 텍스트 액션으로 표시한다. 제목·액션·닫기는 같은 grid 행에서 세로 중앙에 정렬하고 본문은 다음 행 전체 너비를 쓴다. 처리 중에는 `해제 중…`과 원래 disabled 상태를 반영하고, native 재렌더에도 라벨을 복원한다. 닫기·플러그인 해제 시 추가 제목·라벨을 제거하고 원래 카드 표시를 복원한다.

Agentation의 `Send all`·`Discard all`도 제목 행의 `×` 왼쪽에 두고 제목·액션·닫기를 세로 중앙에 정렬한다. `Send all`은 native `ArrowUp`, `Discard all`은 개별 행의 native `Trash2`를 재사용한 공통 24px 아이콘 버튼이다. 텍스트는 시각적으로 숨기고 tooltip과 접근성 이름은 유지한다. `Sending…`과 disabled는 native 상태를 따르며 `Retry`는 텍스트 버튼으로 남긴다. 아이콘이 아직 없으면 기존 텍스트를 유지한다. 닫기·해제 시 추가 아이콘과 접근성 속성을 원상 복구한다. native 헤더 wrapper를 `display:contents`로 풀고 액션 wrapper를 같은 grid 행에 배치하며 버튼의 DOM 부모·핸들러·disabled 상태를 유지한다. 액션은 줄바꿈하지 않으며 좁은 폭에서는 제목만 말줄임한다. 본문은 다음 행 전체 너비를 쓴다.

팝오버 닫기 버튼은 Child Thread·Agentation·native 상세·전체 정보·빈 상태·Diff 모두 24px 원형 영역과 12px `×`를 공유한다. 글자 굵기는 400, line-height는 1이며 flex로 중앙 정렬해 제목의 글자 크기·굵기를 상속하지 않는다.

팝오버 제목은 읽기 전용이다. native 제목 disclosure의 사용자 클릭·Enter·Space는 본문을 접지 않으며 제목에는 hover 배경·pointer·추가 Tab 정지를 두지 않는다. pill·×·Escape와 실제 액션, 본문 안의 목록 펼치기는 유지한다. 닫기·해제하면 native 제목의 원래 속성과 동작을 복구한다. 제목은 공통 28px 행에서 12px/16px·굵기 600·왼쪽 정렬이다. ×는 카드 위 18px·오른쪽 24px의 공통 위치를 사용하며 제목 높이를 별도로 측정하지 않는다. 제목·액션·본문의 DOM 부모는 옮기지 않는다.

To-do·Workflow·백그라운드 작업의 목록 행 밀도와 팝오버 공통 디자인은 `docs/composer-popovers.md`를 따른다. native 상태별 여백과 부모 gap·space-y margin이 중복되지 않도록 하며, 계층·실제 액션·DOM 부모는 유지한다.

데스크톱에서는 정보 pill·전체 정보 원 버튼 위에 mouse pointer가 180ms 머물면 팝오버를 미리 연다. 기기는 `DeviceChromeBridge`의 `desktop` 값을 사용하며 화면 폭으로 판단하지 않는다. phone·tablet·touch·pen에는 hover 열기를 적용하지 않는다. pointer가 pill과 열린 카드 사이를 이동하면 유지하고, 둘 다 벗어나면 150ms 뒤 닫는다. 미리 열린 pill을 클릭하면 닫지 않고 고정하며 다음 클릭은 기존처럼 닫는다. 팝오버 내부의 pointerdown·키보드 포커스·전체 정보 항목 선택도 열린 상태를 유지한다. 클릭으로 연 카드나 편집 중인 큐를 다른 pill의 hover로 교체하지 않는다. 입력 요청·스레드 이동·해제 시 hover 타이머를 취소하고, hover에는 햅틱을 추가하지 않는다.

전체 정보 목록과 모든 상세 팝오버의 카드 자체 패딩은 세로 `16px`·좌우 `24px`, 너비 계산은 `border-box`로 통일한다. 큐 본문에만 추가되던 가로 패딩은 제거해 제목과 본문이 같은 공통 시작점을 사용한다. native Parent·Plan·Goal·할 일·Workflow·백그라운드 작업·실행 환경·스레드 상태·모델 fallback의 본문 레이아웃에 남은 `px-3`·`px-2.5`와 헤더의 `p-1`·segment 가로 패딩은 열린 팝오버에서만 제거한다. 실제 액션 버튼의 패딩과 중첩 목록의 계층 들여쓰기는 유지하고, 할 일 행의 8px 여백은 좌우 margin -8px로 보정한다. 제목 오른쪽에 공통 32px 닫기 여백을 남긴다. 개별 본문·목록·행에 둔 기존 내부 여백은 유지하되 Child Thread와 Agentation의 본문 행은 가로 패딩 8px, 좌우 margin -8px, 너비 calc(100% + 16px)로 둔다. 내용은 제목과 같은 왼쪽 시작점에서 표시하고 hover 배경에는 좌우 8px 여유를 준다. Child Thread와 Agentation의 행은 공통 8px 패딩·hover·둥근 모서리를 쓰고 내용에 따라 높아진다. Parent도 공통 세로 16px·가로 24px 카드 패딩을 사용한다. 행은 Child Thread와 같은 모서리 10px, 패딩 8px, pointer, hover·focus foreground 6%, 공통 최소 높이 32px를 쓴다. 긴 제목은 말줄임하고 24px 닫기 자리를 남긴다. 원래 링크·disclosure와 DOM 부모는 유지하며 닫기·해제 시 추가한 행을 제거한다. Status 등 custom 아이콘의 pill·목록 래퍼도 builtin 아이콘과 같은 16px 정사각형에서 중앙 정렬한다.

정보 줄이 관리하는 대기 큐의 액션 묶음에는 native `::before`의 왼쪽 takeover 그라데이션을 표시하지 않는다. 목록 안쪽에 불투명한 배경이 남지 않도록 하고, 팝오버 glass와 위·아래 스크롤 힌트는 유지한다. standalone 큐의 원래 효과는 유지한다.

Diff 팝오버의 미커밋 요약은 `HEAD · +N −N · N files`로 표시한다. 전체 비교 의미는 툴팁과 접근성 라벨에 유지한다. 커밋 제목은 `origin/<base> → HEAD · 커밋 아이콘 N`으로 줄이고, PR 후보·미푸시 구분은 툴팁과 접근성 라벨에 유지한다. 개수를 확인하지 못하면 `—`로 표시하며 목록 길이로 대체하지 않는다. `HEAD~`는 이전 커밋을 뜻하므로 작업트리 기준 표기로 쓰지 않는다.

첫 등장 모션은 물방울처럼 늘어나고 눌리는 squash/stretch다. 8px 아래의 `scale(.82,.72)`에서 시작하고, 35% 시점에는 4px 위의 `scale(.94,1.16)`로 세로로 늘어난다. 65%에는 제자리의 `scale(1.1,.94)`로 가로로 살짝 눌리고, 82%에는 1px 위의 `scale(.985,1.015)`를 거쳐 460ms에 원래 크기로 돌아온다. CSS 아바타와 Web Animations 필은 같은 단계와 각 구간의 `cubic-bezier(.36,0,.18,1)`을 사용한다. Child Thread 완료의 기존 반응은 360ms에 100% → 110% → 100%다. 정보 pill과 전체 정보 배지의 내용 변화는 420ms `eventHop`이다. 같은 갱신에서 처음 보이는 pill과 Child Thread 아바타는 왼쪽부터 45ms씩 간격을 두고 시작한다. 지연 중에도 첫 자세를 유지하며 숨겨진 pill은 순서에 포함하지 않는다.

대기 메시지 개수는 native header의 `data-queued-messages-count` 안 현재 숫자만 읽는다. 이 속성이 없는 기존 숫자 구조도 지원하며, 읽기용 복사본에서 `aria-hidden`, 이전 숫자 속성, `bb-count-roll-out` 노드를 제외하고 숫자만 검증한다. 실제 여러 자리 개수는 잘라내지 않는다. 롤아웃 중인 이전 숫자와 대기 시간 표시는 제외한다. 개수 변경도 정보 줄의 갱신 기준에 포함해 추가·전송·삭제 직후 pill 숫자와 접근성 라벨을 함께 갱신한다.

정보 pill·전체 정보 버튼으로 여는 팝오버는 8px 아래·98% 크기·투명 상태에서 시작해 260ms 동안 위로 올라오며 원래 크기와 불투명도로 나타난다. 카드와 별도 레이어인 위·아래 스크롤 블러는 등장 전환 중 숨기고, 전환 종료·취소 후 카드의 실제 가장자리를 다시 계산해 표시한다. 블러만 먼저 보이거나 카드 아래로 남지 않게 한다. 하단 중심을 기준으로 확대하며, 호스트 위치 고정의 `transform:none !important`와 충돌하지 않도록 독립 `translate`·`scale`을 사용한다. 모바일·데스크톱에 같은 전환을 적용하고 `prefers-reduced-motion`이면 바로 표시한다.

Code Diff 상단 pill의 추가·삭제 줄 수, 파일 수와 커밋 수가 바뀌면 해당 숫자만 180ms 동안 룰렛처럼 위로 넘기고, 숫자만 바뀌면 pill의 `eventHop`은 재생하지 않는다. 브랜치나 아이콘 등 숫자 외 표시가 바뀌면 `eventHop`은 유지한다. 이전 숫자는 위로 사라지고 새 숫자는 아래에서 올라오며 최신 값과 접근성 라벨은 즉시 갱신한다. 이전 값은 aria-hidden의 CSS 표시로만 남겨 실제 텍스트에 섞지 않고 전환 종료 시 제거한다. 첫 표시·첫 로딩 완료·숨겨진 pill·모션 감소 설정에서는 숫자 모션을 생략하며 브랜치명과 변하지 않은 숫자는 움직이지 않는다. 빠른 연속 갱신은 마지막 실제 값을 기준으로 교체하고 관련 없는 정보 갱신은 진행 중인 모션을 유지한다.

모든 정보 pill이 데이터 소멸·설정 변경·너비 부족으로 사라질 때는 200ms 동안 왼쪽 가장자리를 기준으로 88% 크기로 줄어들고 흐려진다. 클릭·포커스·접근성에서 제외한 시각용 복사본을 원래 flex 순서에 남기고 너비·가로 패딩·간격을 함께 줄여 주변 pill도 자연스럽게 이동하게 한다. 진행 중 너비 전환의 현재 크기를 복사한 뒤 원래 모션을 취소한다. 퇴장 중 자리 너비도 상단 fit 계산에 포함하고, 완료 후 다시 배치한다. 새 pill의 삽입·순서·가용 너비 변화로 기존 pill의 가로 위치가 바뀌면 이전 위치에서 새 위치로 280ms, `cubic-bezier(.22,1,.36,1)`로 이동한다. 위치 이동은 독립 `translate`를 사용해 등장 droplet의 `transform`과 함께 재생한다. 너비 전환·퇴장으로 생기는 빈자리는 실제 flex 슬롯의 너비 감소를 따라 채운다. 빠른 연속 이동은 현재 화면 위치에서 이어 가고, 스레드 이동·해제 시 이동 상태를 정리한다. 결과가 다시 생기거나 다른 스레드로 이동·입력 요청·설정 변경·해제 시 퇴장 모션과 복사본을 정리한다. 숨겨진 pill과 `prefers-reduced-motion`에서는 즉시 제거한다.

대기 큐의 메시지가 추가될 때마다 `stickyDrop`으로 전송 버튼에서 큐 pill로 날아간다. 전송 버튼이 없으면 해당 컴포저 입력 영역의 좌표에서 시작하되, 분리된 출발점으로 처리해 입력 영역 자체에는 찌그러짐 모션을 적용하지 않는다. 방울은 `body`의 `.bbk-drop`이고, 표면은 정보 줄과 같은 glass face·edge 변수를 쓴다. `z-index`는 54다. 전송 버튼을 출발점으로 찾은 경우에만 360ms 동안 찌그러지고, 방울은 460ms 날아가며, 도착한 pill은 380ms 출렁인다. 개수는 도착을 기다리지 않고 즉시 갱신한다. 여러 추가가 한 번에 감지되면 45ms 간격으로 각각 시작한다. 상단 큐 pill이 없으면 큐의 스택 아이콘으로 향하며, 그 아이콘도 표시되지 않으면 +N으로 향한다. 최초 큐 내용은 기준값으로만 읽고, 이후 개수 증가나 실제 메시지 ID 추가·교체를 감지한다. 메시지 행과 개수가 따로 갱신되어도 먼저 도착한 신호로 한 번 재생하고 나중 신호는 중복으로 세지 않는다. 동시에 전송·삭제가 있어 개수가 줄어도 새 ID가 있으면 재생한다. 삭제·재정렬·나중의 목록 렌더링은 새 메시지로 세지 않는다. 같은 스레드에서 본 메시지 ID는 행·큐가 잠시 제거되거나 다시 만들어져도 기억한다. 전체 행이 확인되면 새 ID를 기준으로 도착 수를 정하고, 임시 개수 초기화로 기존 메시지 모션을 반복하지 않는다. 큐 끄기·입력 요청·모션 감소 설정에서는 재생하지 않으며, 스레드 이동과 해제 시 진행 중인 모션·물방울을 정리한다.

접힌 follow-up 입력창은 호스트의 `--follow-up-composer-container-compact:true`를 따라 최소 높이 48px를 유지한다. 확장용 68px 최소 높이가 placeholder·커서 줄을 아래로 밀지 않게 하며, 확장·음성 입력 상태에는 적용하지 않는다.


pill 모션은 `origin/main`의 동작을 유지한다. 기존 등장 460ms·45ms 간격, 내용 변경 eventHop, 숫자 룰렛, 큐 stickyDrop, 퇴장·가로 이동과 Diff 텍스트 fade는 유지하며, 새 재등장 fade와 늦은 초기 데이터 순서 연결은 추가하지 않는다.


정보 스택은 32px 원을 14px 겹치고 Child Thread는 30px 원을 12px 겹쳐, 모두 원 하나마다 18px 늘어난다. 일반 pill은 콘텐츠 기준 auto 너비이며 pill 간격은 8px다. Child Thread의 추가 오른쪽 패딩과 hover 가로 여백은 없다.


새 정보 스택의 첫 펼침만 별도 동작이다. 기존 pill 순차 바운스가 진행된 뒤 +N(없으면 마지막 아이콘)이 기존 460ms 모션으로 등장하고, 45ms 간격·280ms 감속으로 아이콘이 왼쪽부터 펼쳐진다. 스택은 32px에서 콘텐츠 너비로 늘어나며 +N을 오른쪽으로 밀어낸다. 일반 pill의 등장 프레임·opacity·원격 eventHop과 fade는 바꾸지 않는다. 새 재등장 fade·늦은 데이터 순서 연결·끈적 실은 넣지 않는다. 해제 시 지연 중 펼침을 취소하고 reduced motion에서는 즉시 표시한다.

정보 스택 첫 등장에서는 +N에 아직 펼쳐지지 않은 아이콘까지 포함한다. 아이콘이 하나씩 펼쳐지기 시작할 때마다 숫자를 하나씩 빼며, 모두 펼친 뒤에는 실제 나머지 수를 표시한다. 예를 들어 접힌 계열이 13개면 +13 → +12 → +11 → +10이다. 접근성 라벨·툴팁도 같은 수를 쓴다. 펼침 중 재배치가 일어나도 최종 수로 건너뛰지 않으며, 스레드 이동·입력 요청·reduced motion·해제 시 대기 중 숫자 갱신을 취소한다. 일반 pill 모션과 원격 eventHop·fade는 바꾸지 않는다.

정보 줄은 컴포저 안의 DOM 변경, 기기 표시 변경, 호스트 Latest 버튼의 삽입·제거에만 다시 계산한다. 일반 채팅 본문의 스트리밍·속성 변경은 배치 재계산을 예약하지 않는다. 새 컴포저가 중첩된 영역에 삽입되거나 제거되는 경우도 감지한다.

정보 줄이 그린 버튼·팝오버·스택 숫자의 DOM 변경은 새 입력으로 보지 않는다. 특히 +N 펼침 중 숫자·접근성 라벨 변경으로 전체 sync·fit을 다시 실행하지 않는다. native 카드 변경과 SDK 데이터 이벤트는 계속 읽으며, 숨긴 SDK 원본의 provider 아이콘 속성 변경은 해당 원본에서 따로 감지한다. 원본 교체·제거·해제 시 이 관찰도 정리한다.

Plan·Approval 본문 스크롤 블러는 실제 본문 스크롤러가 있을 때만 기준 stack의 크기를 읽는다. 본문이 없는 일반 채팅의 스크롤·모션 종료에서는 이 크기 측정을 생략하되, 사라진 본문의 블러와 관찰 정리는 계속 수행한다.

설정 bridge가 잠시 사라져도 연결된 정보 줄을 해제해 native 카드를 다시 표시하지 않는다. 기존 줄의 자리는 유지하되 보이지 않고 조작할 수 없는 상태로 두고, 열린 팝오버와 진행 중 모션을 정리한다. bridge가 돌아오면 같은 줄에서 최신 정보를 표시한다. 새 native 배너는 다음 프레임의 분류 전에 CSS로 숨긴다. 질문·Secret·Plan·Approval 요청과 본문 스크롤 블러는 이 숨김에서 제외하며 요청의 우선순위를 유지한다. 컴포저 제거 또는 플러그인 해제 시에는 native 표시를 복구한다.

컴포저 정보의 SDK 갱신은 종류별로 나눈다. 현재 스레드의 Goal·Plan·할 일 이벤트는 `summaryOnly` 타임라인만, Child의 제목·실행 상태 변화와 새 Child·보관 해제 후보는 페이지별 Child 목록만, Parent 제목·삭제 이벤트는 해당 부모만 읽는다. 현재 스레드의 보관·환경·Parent 연결·큐·입력 요청 변화는 현재 스레드와 필요한 읽기 전용 정보를 다시 읽고, Parent ID가 바뀔 때만 새 부모를 읽는다. 상태·알 수 없는 현재 스레드 변화와 메타데이터 없는 이벤트는 타임라인·현재 스레드를 보수적으로 다시 읽는다. 일반 토큰 스트리밍·읽음·탭 변화는 조회하지 않는다.

최초 진입·focus·실시간 재연결은 켜진 정보를 모두 동기화한다. 짧은 이벤트 묶음은 기존 250ms 간격으로 합치고, 진행 중 새 변화가 오면 이전 결과를 표시하지 않고 필요한 조회의 합집합으로 재시도한다. 실패한 조회는 마지막 정상 정보를 유지하고 다음 갱신 때 다시 시도하며, 스레드 이동·해제는 대기 작업과 구독을 취소한다. 이 규칙은 `ComposerInfoBridge`에만 적용하고 Diff의 5초 갱신과 native 카드 동작은 유지한다.


설정의 `끄기`는 해당 정보만을 위한 SDK 조회도 중단한다. Code Diff는 조회·구독·5초 타이머·focus 처리를 만들지 않으며, 다시 켜면 최신 상태를 새로 읽는다. Child와 Parent는 각각의 목록·부모 조회를 생략하고, Plan·Goal·할 일·백그라운드 작업을 모두 끈 경우 공유 타임라인 조회를 생략한다. 백그라운드 작업이 켜져 있으면 `activeBackgroundCommands`로 행 아코디언을 갱신한다. `item/backgroundTask/progress`, `item/backgroundTask/completed`, `item/delegation/progress`, `item/delegation/completed`도 타임라인을 다시 읽는다. 읽기 전용 스레드의 큐와 PR도 각 설정을 따른다. `목록에만 표시`, 기존 boolean `false`, 너비 때문에 접힌 항목은 계속 읽는다. 설정 로딩 중에는 조회를 시작하지 않으며, 설정 변경·스레드 이동·해제는 이전 조회를 abort하고 후속 조회·늦은 결과를 막는다.

보관·환경 제거의 안내와 복구는 필수이므로 현재 스레드의 공통 context 조회는 유지한다. 한 정보를 꺼도 다른 켜진 정보에 필요한 공유 조회는 유지한다. 예를 들어 Goal만 끄면 Plan·할 일의 타임라인은 계속 읽고, PR 표시를 꺼도 Code Diff가 켜져 있으면 비교 기준을 위한 PR 조회는 유지한다. native BB 카드와 다른 플러그인의 조회를 끄는 기능은 아니다.

Diff의 작업트리·원격 비교와 커밋 수는 화면이 보이는 동안 5초마다 읽는다. PR 정보만 같은 환경에서 최대 30초 동안 재사용한다. 별도 타이머를 추가하지 않고 기존 갱신에서 만료를 확인하며, 최초 진입·다시 켜기·focus·환경 변경은 30초를 기다리지 않고 PR도 새로 읽는다. 정상 연결에서 PR 생성·대상 변경의 반영은 최대 30초 늦을 수 있다. PR 조회가 실패하면 같은 환경의 마지막 정상 PR 기준을 유지하고 다음 5초 갱신에 재시도한다. PR 없음이 확인되면 그 결과를 새 기준으로 재사용한다. 다른 환경의 캐시와 늦게 도착한 이전 조회 결과는 사용하지 않는다.

대기 큐의 왼쪽 재정렬 핸들은 native 음수 왼쪽 margin을 0으로 덮어 스크롤 영역 안에 둔다. `device`가 desktop이고 실제 카드 너비가 340px 이상이면 native 전송·편집·삭제 버튼을 행 오른쪽에 바로 표시한다. 버튼은 테두리·기본 배경 없이 radius 10px와 기존 액션 메뉴의 hover 배경을 쓴다. 더 좁은 카드와 phone은 기존 `…` 버튼과 액션 팝오버를 유지한다. 너비는 열린 큐에만 ResizeObserver로 관찰하며 진입 transform의 시각적 너비는 쓰지 않는다.

대기 메시지 편집 중에는 큐 목록·목록 제목·닫기를 숨기고 native rich editor를 단일 glass dialog로 표시한다. 메시지 본문은 내용만큼 늘어나며 Code Diff와 같은 최대 높이에 닿은 뒤 본문만 스크롤한다. 첨부·음성 등 사용 가능한 native 기능과 저장 체크 아이콘을 하단에 고정한다. 모델·권한·실행 설정은 대기 메시지 편집에서 변경할 수 없으므로 버튼과 native footer를 숨긴다. 현재 값 안내용 아이콘·팝오버도 만들지 않는다. 큐 `…` 액션 팝오버의 전송·편집·삭제 버튼은 실제 클릭당 `selection` 햅틱을 한 번 내며 native 버튼으로 전달하는 합성 클릭은 중복 처리하지 않는다. 편집의 `+`·음성 입력은 실제 클릭당 `selection` 햅틱을 한 번 낸다. 저장 체크는 native가 터치 pointerup에서 저장하고 click을 막으므로, 같은 버튼에서 시작해 10px 이내로 움직이고 버튼 안에서 끝난 primary touch pointerup에서 한 번 낸다. 취소·버튼 밖 릴리스·disabled·busy에는 울리지 않고 뒤따르는 click은 중복 처리하지 않는다. 마우스·키보드는 실제 click을 사용하며 합성 클릭·저장 submit도 중복 진동을 만들지 않고, 편집 저장은 새 메시지 전송이나 응답 완료 감시를 시작하지 않는다. disabled와 haptic capability가 없는 환경은 울리지 않는다. 일반 컴포저의 선택 메뉴는 유지하며 native DOM과 disabled 상태는 바꾸지 않는다. 편집 도구 버튼은 coarse pointer에서도 32px 높이와 padding 0으로 세로 중앙에 두고 첨부 버튼은 음수 여백 없이 수축하지 않게 둔다. 저장 체크는 비활성 의미와 원래 저장 동작을 유지하되 흐리게 하지 않는다. 큐의 … 선택자는 `Queued message `로 시작하고 ` actions`로 끝나는 버튼만 포함하며 native `Prompt actions`는 숨기거나 클릭을 가로채지 않는다. 별도 footer나 안쪽 카드 면은 추가하지 않는다. React 소유 DOM과 버튼 핸들러는 유지한다. 큐의 외부 스크롤 wrapper만 display:contents로 풀며, native 컴포저의 측정용 form과 wrapper는 크기를 측정할 수 있는 투명한 box로 남긴다. 원래 submit을 저장 아이콘으로 표시하고 제목 우측의 native ×는 취소다. 입력만으로 저장하지 않으며 저장 성공 또는 취소 뒤 열린 큐 목록으로 복귀한다. 실패·비활성 상태는 native 동작을 따른다. Escape는 멘션 후보와 IME 조합 중을 제외하고 편집만 취소한다. 해제 시 추가 아이콘·속성만 복구하고 초안 DOM은 유지한다. 큐 행의 핸들과 …는 24px이며 위 여백 없이 한 줄·여러 줄 메시지 행 전체의 세로 중앙에 둔다. 본문 세로 패딩은 large hit target에서 8px, small에서 4px다.

정보 카드의 단일 행·본문 가장자리·닫기 규격과 native/SDK 연결은 `docs/composer-popovers.md`의 공통 규격 표를 따른다. 닫기는 공통 오른쪽 16px, 기본 제목 행에서는 위 18px, Parent·PR의 32px 단일 행에서는 위 20px다. native 본문의 중복 상하 패딩을 없애고 SDK 본문은 `cardSlot.body`에 연결한다. 목록 행 자체의 8px 패딩은 유지하며 Queue의 제목·본문 간격도 공통 8px를 쓴다.
