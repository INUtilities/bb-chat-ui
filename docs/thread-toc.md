# 목차 미리보기

넓은 채팅 화면의 native 목차와 기존 눈금·메시지 이동을 사용한다.
BB는 사용자 메시지 요약 목록에서 최대 20개 눈금을 뽑고 현재 보이는 메시지를
포함할 수 있다. 눈금 수는 전체 메시지 수가 아니다. 눈금과 목록 항목의 native ID를
직접 연결하며 카드 안의 원형 아이콘은 눈금으로 세지 않는다. ID가 확인됐지만 해당
목록 행이 아직 없으면 다른 메시지로 이동하지 않고 native 목록 갱신을 기다린다.
선택한 사용자 메시지는 12px/16px·600의 한 줄 말줄임으로 표시한다.
그 아래에는 에이전트 응답을 11px/18px·400과 `--muted-foreground`로 최대 6줄 표시한다.
카드 최소 높이는 96px, 바깥 모서리는 18px이며 기존 최대 높이와 glass 표면은 유지한다.
지원하는 브라우저에서는 기존 시안의 36px 스쿼클 모서리를 적용하며 미지원은 18px 둥근 모서리를 유지한다.

포인터의 첫 진입은 즉시 처리하고 이후 이동은 표시 프레임에 합친다. 원격 main의 native ID 연결과 눈금 전체를 읽은 뒤 너비를 쓰는 순서는 유지한다. 이탈·제거·해제에서 예약 작업을 취소한다.

## 대화 연결

공개 SDK의 `threads.conversationOutline({ threadId, signal })`을 역할 필터 없이 읽는다.
현재 화면에 로드되지 않은 과거 사용자 메시지도 같은 목차의 ID로 연결한다.
응답은 API가 제공한 대화 순서에서 선택한 사용자 뒤부터 다음 사용자 앞까지의
마지막 비어 있지 않은 에이전트 `preview`다. 전체 응답 원문을 별도로 읽지는 않는다.
문장 일치 추정은 하지 않으며, 읽을 수 없거나 해당 ID가 없는 자료는 안내로 표시한다.

SDK owner는 창마다 한 번 등록하며 읽기 전용 스레드와 여러 pane에도 제공한다.
실제 조회는 목차를 열어 항목을 표시할 때만 시작한다. 열린 목차 안에서는 요청과
ID별 응답 색인을 공유하므로 눈금을 옮길 때마다 조회하지 않는다. 닫으면 요청과
캐시를 해제하고, 다시 열면 최신 요약을 읽는다. 별도 polling은 하지 않는다.
닫기·스레드 교체·SDK owner 해제 뒤 도착한 결과는 표시하지 않는다.

목차의 `aria-controls`에서 스레드 ID를 확인하고 native 사용자 항목의 React key를 쓴다.
눈금의 React key도 같은 ID 계약을 사용한다. key가 없는 구형 DOM에서는 기존 비례
연결을 유지한다. 포인터 이동은 모든 눈금의 크기를 먼저 한 번씩 읽은 뒤 변경된
너비만 쓴다. 같은 눈금 안에서 움직일 때는 카드 내용을 다시 그리지 않는다.
이 DOM ID·key 연결은 공개 SDK 계약이 아니므로 BB 갱신 때 재검증해야 한다.
부모 React 트리와 `timelineRows`는 읽지 않으며 다른 스레드의 캐시를 재사용하지 않는다.
원래 사용자 버튼과 이동 콜백은 유지하고, 플러그인 소유 응답 span만 추가·제거한다.
목차를 떠나거나 레일·목차가 제거되거나 플러그인이 해제되면 소유 span을 정리한다.
